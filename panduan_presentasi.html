Langkah 2: Pembuatan File Migration (Memperhatikan Urutan Dependency)

Migration dibuat menggunakan perintah artisan. Poin penting yang sangat diperhatikan dosen adalah urutan pembuatan file karena adanya Foreign Key Constraint.

Urutan Perintah Artisan Nama Tabel Keterangan Ketergantungan (Dependency)
1 php artisan make:migration create_members_table members Tabel Master (Independen)
2 php artisan make:migration create_authors_table authors Tabel Master (Independen)
3 php artisan make:migration create_publishers_table publishers Tabel Master (Independen)
4 php artisan make:migration create_books_table books Bergantung pada authors & publishers
5 php artisan make:migration create_loans_table loans Bergantung pada members & books
💡 Pertanyaan Jebakan Dosen:

Dosen: "Kenapa tabel authors dan publishers harus dibuat SEBELUM tabel books?"
Jawaban Anda: "Karena tabel books memiliki Foreign Key author_id dan publisher_id yang mereferensikan primary key dari tabel authors dan publishers. Jika tabel books dimigrasi lebih dulu sebelum tabel referensinya ada di MySQL, maka database akan melempar error Foreign Key Constraint is incorrectly formed."

Detail Isi Kode Migration:

1. create_books_table.php:

Schema::create('books', function (Blueprint $table) {
    $table->id();
    $table->string('title');
    $table->foreignId('author_id')->constrained()->onDelete('cascade');
    $table->foreignId('publisher_id')->constrained()->onDelete('cascade');
    $table->timestamps();
});

Keterangan: Method constrained() secara otomatis mendeteksi tabel referensi berdasarkan konvensi nama kolom (contoh: author_id merujuk ke authors.id). Opsi onDelete('cascade') memastikan jika data author dihapus, semua buku karyanya otomatis ikut terhapus demi integritas data.

2. create_loans_table.php:

Schema::create('loans', function (Blueprint $table) {
    $table->id();
    $table->foreignId('member_id')->constrained()->onDelete('cascade');
    $table->foreignId('book_id')->constrained()->onDelete('cascade');
    $table->date('loan_date');
    $table->date('return_date')->nullable(); // nullable karena saat meminjam buku belum dikembalikan
    $table->timestamps();
});

Langkah 3: Pembuatan Model Eloquent & Relasi Antartabel

Model dibuat dengan perintah php artisan make:model <NamaModel>. Di dalam model, kita mendefinisikan properti $fillable untuk keamanan serta relasi antar tabel (One-to-Many).

Model File Relasi yang Didefinisikan Kode Relasi
Author app/Models/Author.php Satu Author menulis banyak Buku (hasMany) public function books() { return $this->hasMany(Book::class); }
Publisher app/Models/Publisher.php Satu Publisher menerbitkan banyak Buku (hasMany) public function books() { return $this->hasMany(Book::class); }
Book app/Models/Book.php Buku milik Author & Publisher (belongsTo) public function author() { return $this->belongsTo(Author::class); }
public function publisher() { return $this->belongsTo(Publisher::class); }
Member app/Models/Member.php Satu Anggota memiliki banyak Transaksi (hasMany) public function loans() { return $this->hasMany(Loan::class); }
Loan app/Models/Loan.php Transaksi merujuk ke Anggota & Buku (belongsTo) public function member() { return $this->belongsTo(Member::class); }
public function book() { return $this->belongsTo(Book::class); }

Langkah 4: Pembuatan Seeder & DatabaseSeeder

Seeder digunakan untuk memasukkan data awal dummy ke dalam tabel tanpa harus menginput manual lewat form.

  • MemberSeeder.php: Memasukkan data anggota Ali dan Budi.
  • AuthorSeeder.php: Memasukkan data penulis Tere Liye dan Andrea Hirata.
  • PublisherSeeder.php: Memasukkan data penerbit Gramedia dan Mizan.
  • BookSeeder.php: Memasukkan data buku Bumi (author_id: 1, publisher_id: 1) dan Laskar Pelangi (author_id: 2, publisher_id: 2).
  • LoanSeeder.php: Memasukkan data transaksi peminjaman buku.

Semua seeder didaftarkan di dalam DatabaseSeeder.php:

class DatabaseSeeder extends Seeder {
    public function run(): void {
        $this->call([
            MemberSeeder::class,
            AuthorSeeder::class,
            PublisherSeeder::class,
            BookSeeder::class,
            LoanSeeder::class,
        ]);
    }
}

Langkah 5: Eksekusi Migrasi & Seeder Secara Sekaligus

Untuk menjalankan seluruh migrasi dari keadaan bersih dan langsung mengisinya dengan seeder, jalankan:

php artisan migrate:fresh --seed
🗣️ Penjelasan ke Dosen:

"Perintah migrate:fresh --seed akan menghapus seluruh tabel yang ada di database digital_library terlebih dahulu, menjalankan ulang seluruh file migrasi dari awal secara berurutan, lalu secara otomatis mengeksekusi kelas DatabaseSeeder untuk mempopulasikan data dummy ke dalam tabel."

Metode 3: Menampilkan Output Melalui Database MySQL Langsung (SQL Query)

Jika dosen meminta dibukakan MySQL Command Line atau phpMyAdmin:

Perintah SQL JOIN untuk Membuktikan Relasi Foreign Key Bekerja:

mysql -u root
USE digital_library;

-- Query 1: Menampilkan Buku + Penulis + Penerbit
SELECT b.id, b.title, a.name AS Penulis, p.name AS Penerbit
FROM books b
JOIN authors a ON b.author_id = a.id
JOIN publishers p ON b.publisher_id = p.id;

-- Query 2: Menampilkan Data Peminjaman Lengkap
SELECT l.id, m.name AS Peminjam, b.title AS Judul_Buku, l.loan_date, l.return_date
FROM loans l
JOIN members m ON l.member_id = m.id
JOIN books b ON l.book_id = b.id;

4. Bocoran Tanya Jawab Kritis Dosen (Q&A Defense)

Berikut adalah pertanyaan yang hampir pasti diajukan oleh dosen penguji beserta jawaban terbaiknya:

Q1: Apa fungsi properti $fillable pada Model Eloquent?
Jawaban: Properti $fillable berfungsi sebagai proteksi terhadap celah keamanan Mass Assignment Vulnerability. Properti ini mendefinisikan kolom mana saja yang diizinkan untuk diisi secara massal saat menggunakan method seperti Model::create($request->all()). Jika tidak didefinisikan, Laravel akan melempar MassAssignmentException demi mencegah pengguna menyisipkan kolom berbahaya.
Q2: Apa perbedaan php artisan migrate, migrate:rollback, dan migrate:fresh?
Jawaban:
  • migrate: Hanya mengeksekusi file migrasi baru yang belum pernah dijalankan (melihat tabel migrations).
  • migrate:rollback: Membatalkan/menjalankan method down() pada batch migrasi terakhir.
  • migrate:fresh: Menghapus (drop) seluruh tabel di database tanpa menjalankan down(), lalu membuat ulang seluruh tabel dari awal.
Q3: Apa yang dimaksud dengan N+1 Problem pada Eloquent dan bagaimana mengatasinya?
Jawaban: N+1 Problem terjadi ketika kita mengambil kumpulan data utama (1 query), lalu melakukan loop dan memanggil relasi di setiap baris sehingga memicu query baru sebanyak N kali (total 1 + N query). Solusinya adalah menggunakan teknik Eager Loading dengan method with(), misalnya Book::with('author')->get(), yang hanya membutuhkan 2 query SQL saja terlepas dari seberapa banyak jumlah buku yang diambil.
Q4: Apa arti onDelete('cascade') pada relasi Foreign Key?
Jawaban: Aturan ini memastikan integritas referensial. Apabila baris data induk (misalnya record Author) dihapus dari database, maka seluruh data anak yang berelasi dengannya (semua Buku yang ditulis oleh author tersebut) akan otomatis ikut dihapus oleh sistem database, sehingga tidak menyisakan data yatim (*orphan data*).
